navegacion|Page navigation|Open a detail screen and return to the list.|Mental model: Pages contain components. Go to page switches to a page within the same project. Exported apps start on the first page.||Exercise: Add a page named Details. / Add a View details button to the first page. / Attach Go to page to its On click event and select Details. / Add a Back button on Details and connect it to the first page.||Troubleshoot: If nothing happens, check the selected event, the block connection, and whether the destination exists. Test both directions in the exported app.
validacion|Conditions and forms|Check input before saving a row.|Mental model: A condition returns true or false. If / else runs one branch. Combine two comparisons with AND.||Exercise: Add a Material field and a numeric Quantity field. / Connect If / else to the Save button. / Combine Material is not empty and Quantity is above zero. / Insert the row in Then. In Else show Enter a material and a positive quantity.||Check each case: Try an empty value, zero, and a valid quantity. Only the third should add a row. Use Trim spaces on the text if whitespace should count as empty.
expresiones|Variables and expressions|Calculate values without repeating input.|Mental model: Component value reads the current value. An expression combines values. Set variable stores a result for later actions.||Exercise: Add two numeric fields, Units and Price. / For Calculate, set total to Units × Price. / Use Show message with Join text to display the result.||Check: With 3 units at 20, the result should be 60. Try an empty field and add a condition before calculating if you need to require both values.
funciones|Reusable functions|Run the same workflow from different buttons.|When to use a function: Group actions for a repeated task using New function. Trigger the function from a button event using Call function.||Exercise: Create a function named Notify. / Attach Show message below its heading. / Add two buttons to a page. / Connect Call function to each button event and choose Notify.||Check: Test each button and confirm it shows the same message. Edit the message in the function and test both events again.
medios|Images and icons|Use local assets to design an interface that works offline.|Choose assets: Local PNG, JPEG, WebP and GIF files are embedded in your project. Use images you own or have permission to use. HTTPS resources require connectivity.||Exercise: Add an Image component and choose Upload image in Properties. / Try Contain to show the entire image or Cover to fill the frame. / Add an icon to a button and place it on the right.||Check: Test the interface at two widths. Make sure the crop preserves the subject and the button still has a readable label.
adaptacion|Responsive layout|Test the same project at narrow and wide widths.|Mental model: The canvas size is your editing reference. Anchors control how each component moves or stretches when the space changes.||Exercise: Start with Mobile. / Add a heading and a panel. / Set the panel’s horizontal anchor to stretch as the width changes. / Use Show on screen if a component only belongs on wider screens.||Check: Choose Test and change the width. Keep the heading visible and prevent controls from overlapping. Adjust margins and dimensions, then test again.
datos-operaciones|Update and count rows|Work with existing records as well as inserting them.|Reference: Rows have a position and data blocks use row numbers starting at 1. Connect column values in header order.||Exercise: Create a table with Material and Quantity columns and add two sample rows. / Add a numeric field to select the row. / Attach Update row and supply values in order. / Add a second button using Row count and Show message.||Check: Update the second row and confirm the first stays the same. Test an out-of-range index before adding a delete button.
depuracion|Troubleshooting and testing|Find out why an action does not run.|Start at the event: Select the component and choose Edit logic. Check that blocks are connected below the correct event. Loose blocks are saved for editing and are excluded from execution.||Exercise: Add a temporary Show message at the start of the event. / Choose Test and use the control. / If the message appears, inspect the condition or target of the next action. / If it does not appear, check the event and connection.||Check the export: When Test closes, its tables return to the project state. Repeat the workflow in the generated HTML to check persistence or navigation from the beginning.
referencia|Editor reference|Look up each part of Studio and choose the right file.|Design: Place components and adjust position, text, dimensions, and appearance. Layers helps select overlapping components.||Logic and data: An event runs connected actions. Values and conditions feed those actions. Data contains the project’s tables.||Files: Import a JSON backup to continue editing. HTML and EXE files are for running your app. CSV exchanges rows and requires compatible headers.||Examples: Open Campus Reserva from the library. Choose Edit a copy to explore its pages, table, date picker, and blocks while preserving the demo.
proyecto-completo|Build a complete inventory app|Design, validate, save, and export the same project from start to finish.|What you will build: A two-field form records materials. The screen shows saved rows, rejects invalid quantities, and downloads a CSV file. Keep Studio open and use sample data.||Exercise: Create a project called Inventory and select Desktop. / Add a Material Input, a Quantity Number, a Register Button, and a Table. / In Data, create Materials with the headers Material,Quantity. / Return to Design and select Materials in the Table properties. / Select Register and choose Edit logic. Attach If / else to its event. / Combine Material is not empty and Quantity is above zero. / In Then, add Insert row. Attach the Material field value followed by the Quantity value. / In Else, use Show message with Check your entries. / Add a CSV button and attach Download table as CSV with Materials as the target.||Test a set of cases: Try saving an empty row. Then enter Markers and 0. Both should show the message and leave the table unchanged. Enter Markers and 8. You should see a row with those values.||Export and repeat: Close Test, export Standalone HTML, and open it. Its initial state comes from the project, so add a row in the exported app. Download the CSV and check that the first line has the headers and the next line has your row.||Go further: Add a summary page, a navigation button, and a chart bound to Materials. Use Row count in a message to compare the number of records before and after saving.
acceso|Practice sign-in form|Read the demo and identify the two branches of the form.|What you are testing: Campus Reserva uses fictitious values and local logic to teach comparisons and navigation. A local form is useful for practice. Avoid using real passwords or treating it as production authentication.||Exercise: Open Campus Reserva and choose Edit a copy. / Select Entrar and choose Edit logic. / Inspect the If / else condition and identify which fields it compares. / Add Show message at the end of Else to explain what to check. / In Test, first try an incorrect value and then use the guided exercise values.||Check: An incorrect value should leave you on the form. Correct values take you to Mis reservas. The extra message should appear only in the incorrect branch.
csv|Import and export CSV files|Test the path between Studio and a spreadsheet.|Prepare a sample: Create a CSV with the headers Material,Quantity and a row such as Paper,12. Headers must match when importing into an existing table. Use sample data during testing.||Exercise: In Data, create a table with those headers and import the CSV. / Add a Table to the canvas and select its data source in Properties. / Attach Download table as CSV to your app’s export button. / In Test, download the file and verify its header and row.||Troubleshoot: If columns are mixed up, check delimiters, quotes, and headers. If an import adds duplicates, check whether you imported the same file into a table that already had those rows.||Choose what to keep: Data edits are saved with the project. Changes made in Test are temporary. CSV preserves rows and headers. A JSON backup preserves the full project.
accesibilidad|Accessibility checks|Check readability, controls, and navigation before sharing.|Name your controls: Write labels that explain what happens when a button is clicked. When color indicates success or a problem, also display a text message.||Exercise: In Test, tab through your form. / Use the keyboard to operate controls where possible. / Zoom in and check whether titles, fields, and buttons remain visible. / Repeat the workflow in the exported file.||Check the result: Try completing the inputs, correcting a mistake, and moving to the next page. If an icon is the only way to recognize a button, add text that names its action.
